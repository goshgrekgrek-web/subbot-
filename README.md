# SubBot — подписка на закрытый Telegram-канал

Бот выдаёт доступ в приватный канал и принимает оплату через **Crypto Pay (@CryptoBot)**
и **Tribute**. Оплата подтверждается вебхуками, доступ выдаётся автоматически.

```
        ┌──────────────┐   /start, тариф   ┌─────────────────┐
        │              │ ────────────────► │                 │
        │  Пользователь│                   │   Ваш бот       │
        │              │ ◄──────────────── │  (aiogram 3)    │
        └──────┬───────┘   ссылка в канал  └────┬───────┬────┘
               │                                │       │
        платит ▼                          webhook│       │webhook
        ┌──────────────────┐           ┌─────────▼──┐  ┌─▼────────────┐
        │ CryptoBot /      │ ────────► │ /webhook/  │  │ /webhook/    │
        │ Tribute          │  invoice_ │ cryptopay  │  │ tribute      │
        └──────────────────┘  paid     └────────────┘  └──────────────┘
                                              │
                                              ▼  createChatInviteLink(member_limit=1)
                                        закрытый канал
```

## Как это работает

1. `/start` → бот показывает тарифы.
2. Кнопка тарифа → `createInvoice` в Crypto Pay → пользователь платит.
3. CryptoBot шлёт `invoice_paid` на `/webhook/cryptopay` → бот создаёт **одноразовую**
   инвайт-ссылку (`member_limit=1`, TTL 30 мин) и присылает её в чат.
4. Подписка истекает → планировщик исключает человека из канала и пишет ему об этом.
5. Продление: дни **складываются** к текущей дате окончания, а не сбрасывают её.

## Быстрый старт

```bash
cp .env.example .env      # заполнить значения
pip install -r requirements.txt
python -m app.main
```

Или в Docker:

```bash
docker build -t subbot .
docker run -d --env-file .env -p 8080:8080 -v $(pwd)/data:/app/data subbot
```

## Настройка Telegram

1. `@BotFather` → `/newbot` → сохранить `BOT_TOKEN`.
2. Добавить бота в приватный канал **администратором** с правами:
   - *Приглашать пользователей* (создание ссылок),
   - *Блокировать участников* (исключение по окончании).
3. Узнать `CHANNEL_ID` (формат `-100...`). Проще всего — переслать сообщение из
   канала боту вроде `@username_to_id_bot`.

## Настройка Crypto Pay

1. Открыть `@CryptoBot` → **Crypto Pay** → **My Apps** → создать приложение.
2. Взять токен → `CRYPTO_PAY_TOKEN`.
   Для тестов: `@CryptoTestnetBot` и токен оттуда.
3. Там же **Webhooks** → 🌕 **Enable Webhooks** → указать
   `https://ваш-домен/webhook/cryptopay`.
4. В `.env`: `CRYPTO_ASSET=USDT`, `CRYPTO_PRICE=5`, `CRYPTO_CURRENCY_TYPE=crypto`.

Подпись вебхука проверяется как `HMAC-SHA256(SHA256(token), raw_body)` и сравнивается
с заголовком `crypto-pay-api-signature` — см. `app/cryptobot.py:verify_webhook`.

## Настройка Tribute

Есть два режима. В коде реализован **режим A** — он требует меньше кода и меньше
точек отказа.

**A. Tribute сам управляет доступом (рекомендуется)**
1. В Creator Dashboard создать подписку на канал.
2. Добавить бота `@tribute` админом канала — он сам гоняет инвайты, продления,
   списания и напоминания. У Tribute это основной сценарий, и менять его смысла нет.
3. Dashboard → **⋯ → API Keys** → сгенерировать ключ → `TRIBUTE_API_KEY`.
4. Указать webhook URL: `https://ваш-домен/webhook/tribute`.
5. Всё, что остаётся нашему боту — приём событий `new_subscription`,
   `renewed_subscription`, `cancelled_subscription` для учёта и уведомлений.

**B. Свой чекаут через Shop API** (если хотите тарифы внутри своего бота):
`GET /products` → выбрать продукт → `POST /products/{id}/purchase` → отдать `pay_url`.
Доступом управляем сами через тот же `access.py`.

⚠️ **Главная ловушка двойного канала оплаты.** Если человек платит через Tribute
(там бот следит за доступом сам), а вы его же исключите за неоплаченный инвойс
CryptoBot — вы выкинете платящего клиента. Поэтому `app/access.py:has_any_paid_access`
перед исключением проверяет все источники сразу. Не убирайте эту проверку.

Подпись вебхуков Tribute — заголовок `trbt-signature`, тот же HMAC-SHA256,
ключ = ваш API key. Реализация: `app/tribute.py:verify_webhook`.

## Команды бота

| Команда | Кто | Что делает |
|---|---|---|
| `/start` | все | тарифы или текущий статус |
| `/start pay_30` | все | сразу выставить счёт (deep-link, удобно для постов в канале) |
| `/admin` | админ | статистика: юзеры, активные подписки, оплаты |
| `/grant <tg_id> <дней>` | админ | выдать доступ вручную (промо, компенсация) |
| `/revoke <tg_id>` | админ | снять доступ досрочно (возврат, нарушение правил) |

## Что важно знать про эксплуатацию

- **Идемпотентность.** CryptoPay и Tribute ретраят вебхуки (у Tribute — до 24 часов
  с экспоненциальной задержкой). Таблица `processed_events` гарантирует, что один
  платёж не выдаст две подписки. Каждый вебхук обязан отвечать `200`, иначе ретраи
  не прекратятся.
- **Возврат в канал.** Перед новым инвайтом вызывается `unbanChatMember(only_if_banned=True)`
  — без этого Telegram не впустит человека, которого мы исключили ранее, даже по новой ссылке.
- **Больше 366 дней.** У `banChatMember.until_date` есть граница: дальше 366 дней
  Telegram трактует срок как «навсегда» и не снимет блокировку сам. Если планируете
  годовые тарифы — надёжнее ставить канал в режим *заявок на вступление* и одобрять их
  по базе, чем полагаться на авто-разбан.
- **Планировщик внутри процесса.** `scheduler_loop` живёт в том же процессе, что и бот.
  Для нескольких реплик вынесите его в отдельный сервис или прикрутите блокировку,
  иначе разные реплики будут дублировать исключения.
- **Состояние инвойсов в памяти** (`app/state.py:PLAN_BY_INVOICE`) теряется при рестарте.
  Для одного процесса это не проблема: срок можно восстановить из `payments.external_id`.
  При горизонтальном масштабировании — заменить на Redis.
- **Вебхуки требуют HTTPS.** Polling и так работает за NAT, но вебхуки — нет.
  Минимальный вариант: VPS + Caddy с автоматическим Let's Encrypt, он даёт TLS
  из коробки в конфиге из двух строк. Альтернатива без своего домена —
  Cloudflare Tunnel.
- **Не транслируйте `payload` как есть** между провайдерами: у CryptoPay `payload` —
  это ваша строка (мы кладём туда `tg_id`), у Tribute структура событий другая.
  Разбор — в `app/tribute.py:parse_subscription_event`.

## Тестирование перед продакшеном

1. `@CryptoTestnetBot` + `CRYPTO_CURRENCY_TYPE=crypto`, оплата тестовыми монетами.
2. Проверка повторного вебхука: `curl -X POST /webhook/cryptopay` дважды с одинаковым
   телом — вторая подписка выдаваться не должна.
3. Проверка возврата: `/revoke <id>` → вступить по новой ссылке должно получиться.
4. `python selfcheck.py` — быстрая проверка подписей, разбора событий и схемы БД.
